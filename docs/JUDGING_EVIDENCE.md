# Judging evidence

| Criterion | Demonstrable evidence | Boundary |
| --- | --- | --- |
| Usefulness and local impact | A familiar rotating savings circle with a visible 100-sat obligation, 400-sat target, named recipient, deadlines, and missing members | The scenario is illustrative; no user interviews or adoption data are claimed |
| Security by design | Access-code/CSRF checks, incoming settled invoice and exact hash/amount verification, unique hashes, nonrecipient approvals, audit trail, normally receive-only NWC receiver | Sandbox faucet receiver has spending permission for fake sats; no production custody or independent real payout verification |
| UX quality | Responsive forest/gold interface, clear wallet paths, persistent mobile navigation, readable cycle timeline and receipts, reduced-motion preloader | Device and bandwidth testing is limited to local browser checks |
| Real Bitcoin payment in-app | A judge with any Lightning wallet scans the demo invoice (from the treasurer's receive-only Blink wallet) and pays 100 real sats; CircleSats detects settlement, records the payment hash and preimage, and the judge's own wallet shows the payment | Needs the operator's Blink key on Vercel; first live payment pending |
| Real Lightning payment in-app (test coins) | Each visitor's contribution is a Mutinynet invoice from the circle treasurer node, paid by the Mutinynet faucet over Lightning, credited after treasurer settlement; the receipt shows payment hash and preimage for self-checking | Test coins on a test network; payer is the faucet, not the judge. **First live payment settled 27 Oct 2026** ([evidence](LIGHTNING_PAYMENT_EVIDENCE.md)) |
| Lightning wallet in-app (fallback) | Each visitor's demo wallet is a private Alby sandbox wallet pair: a real BOLT11 invoice, paid over NWC, credited only after receiver settlement and preimage match; visitors are isolated from each other | Test sats, not routed over the public Lightning network; live faucet run pending (`npm run test:guest-sandbox`) |
| Working MVP | Automated four-round guest journey: 16 simulated contributions, 12 approvals, four simulated payouts, retained history, new cycle; separate Alby Sandbox integration: four fake-sat NWC settlements, durable ledger, three approvals | No real Bitcoin/signet or LNbits settlement, and no outgoing Lightning payout |
| Clear pitch | [Presentation](PRESENTATION.md), [public demo](https://circlesats-two.vercel.app/), [three-minute walkthrough](DEMO_WALKTHROUGH.md), [architecture](ARCHITECTURE.md), [security](SECURITY.md), and [setup](TESTNET_SETUP.md) | No video or Devpost entry yet |

Latest verification on 27 October 2026: `npm test` passed 25 tests, `npm run build:vercel` succeeded, `npm audit --omit=dev --audit-level=moderate` reported zero vulnerabilities, and `npm run check:secrets` found no private wallet connections among 64 Git candidate files. The separate Alby Sandbox check passed four 100-sat fake-sat payments, a 400-sat funded round, duplicate rejection, persisted ledger, and three approvals. Local browser checks at 375 px, 615 px, and 1440 px showed no horizontal overflow and working navigation. The public HTTPS Vercel page loaded and its guided simulation started; the local Vercel build completed one funded, approved, simulated round and opened round two. Physical devices remain untested. No real Signet settlement or outgoing payout is claimed.
